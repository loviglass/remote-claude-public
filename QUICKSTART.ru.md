# Remote Claude: руководство пользователя

Remote Claude запускает Claude Code на управляемом Linux-сервере, а в обычном режиме оставляет файлы проекта и выполнение команд на вашем компьютере. Вам не нужно синхронизировать две копии репозитория: Claude работает с локальным проектом через SSHFS, а команды, сборки, тесты, hooks и поддерживаемые MCP выполняются в вашей обычной среде.

Отдельный режим `--server` переносит всю задачу на сервер и позволяет выключить компьютер. Его отличия описаны ниже.

## 1. Что понадобится

- архив клиента для вашей ОС и архитектуры из [Releases](../../releases/latest);
- персональное приглашение `remote-claude-ИМЯ.json` от администратора сервера;
- локальные инструменты проекта: Git, компиляторы, Docker и другие зависимости — только если они нужны самому проекту.

Node.js, Python, WSL и входящий SSH-сервер для клиента не требуются. Пробрасывать порты на роутере не нужно.

**Приглашение — секрет.** Внутри находится одноразовый закрытый ключ регистрации. Не публикуйте файл, не отправляйте его в issue и не храните в Git. После успешной установки удалите его.

## 2. Проверка архива

Скачайте `SHA256SUMS` и сравните SHA-256 выбранного архива с опубликованным значением.

Linux:

```sh
sha256sum remote-claude-VERSION-linux-amd64.tar.gz
```

macOS:

```sh
shasum -a 256 remote-claude-VERSION-darwin-arm64.tar.gz
```

Windows PowerShell:

```powershell
Get-FileHash .\remote-claude-VERSION-windows-amd64.zip -Algorithm SHA256
```

Имя архива зависит от выпуска и платформы: `linux`, `darwin` или `windows`; `amd64` или `arm64`.

## 3. Установка

### Linux и macOS

Распакуйте архив и выполните из распакованного каталога:

```sh
sh ./install.sh /безопасный/путь/remote-claude-ИМЯ.json
```

По умолчанию клиент и `remote-claude-rg` устанавливаются в `~/.local/bin`. Другой каталог можно задать переменной `REMOTE_CLAUDE_BIN_DIR`.

Если каталог ещё не входит в `PATH`, добавьте в `~/.bashrc` или `~/.zshrc`:

```sh
export PATH="$HOME/.local/bin:$PATH"
```

Откройте новый терминал. До этого используйте полный путь `~/.local/bin/remote-claude`.

Сборки macOS не подписаны и не нотарифицированы проектом. Проверяйте источник и SHA-256; не отключайте системную защиту целиком ради установки.

Для обновления вручную тот же установщик запускается без приглашения:

```sh
sh ./install.sh
```

### Windows

1. Распакуйте ZIP через **Извлечь все…**. Запуск из окна архива не сработает.
2. Дважды щёлкните `install.cmd`.
3. При необходимости выберите использование HTTP CONNECT-прокси и укажите его порт.
4. Установщик ищет `remote-claude-*.json` рядом с собой, в «Загрузках» и на рабочем столе. Если приглашение не найдено, перетащите файл в окно.
5. После регистрации согласитесь удалить приглашение.

Альтернатива из PowerShell:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\install.ps1 `
  -Invitation C:\безопасный\путь\remote-claude-ИМЯ.json
```

Клиент устанавливается в `%LOCALAPPDATA%\Programs\remote-claude`. Интерактивный установщик добавляет в контекстное меню папок команды **Открыть в Remote Claude** и **Remote Claude: продолжить разговор**. В Windows 11 они могут находиться в **Показать дополнительные параметры**.

Обычные команды выполняются через PowerShell. Если проект содержит Bash-скрипты или Bash-hooks, установите Git for Windows с Bash; мост не преобразует Bash в PowerShell и не использует WSL автоматически.

Перед заменой файлов при обновлении закройте запущенные клиенты.

## 4. Первый запуск и диагностика

Перейдите в проект:

```sh
cd /путь/к/проекту
remote-claude --check .
remote-claude .
```

`--check` не обращается к модели. Проверяются SSH, чтение и запись файлов, метаданные, список каталогов, локальная оболочка и видимость локальных изменений. В отчёте также есть время операций и SSH round trip.

При первом запуске Claude может попросить подтвердить доверие репозиторию и MCP. Подтверждайте только знакомый проект.

После подключения клиент выводит сервер, локальный путь проекта и ОС, на которой выполняются команды. Завершение — `/exit` в Claude.

### Если нужен HTTP-прокси

SSH можно направить через HTTP CONNECT-прокси:

```sh
remote-claude --proxy --check .
remote-claude --proxy .
```

По умолчанию используется `127.0.0.1:10809`. Другой адрес и порт:

```sh
remote-claude --proxy --proxy-host 127.0.0.1 --proxy-port 20809 .
```

Без `--proxy` прокси не используется. Те же параметры поддерживают `setup`, `ssh`, `night` и `--server`.

## 5. Разговоры и аргументы Claude

```sh
remote-claude --resume .                 # меню выбора разговора
remote-claude --resume=SESSION_ID .      # конкретный разговор
remote-claude --continue .               # самый свежий без меню
remote-claude --print "Объясни проект" . # один неинтерактивный запрос
```

ID для `--resume` указывается только через `=`.

Аргументы Claude Code передаются после пути и `--`:

```sh
remote-claude . -- --model sonnet
```

Для нескольких серверов или наборов доступа используются профили:

```sh
remote-claude setup --profile work /путь/к/приглашению.json
remote-claude --profile work .
remote-claude --profile work ssh
```

Профили хранятся в системном каталоге конфигурации пользователя:

| ОС | Каталог |
|---|---|
| Linux | `~/.config/remote-claude/` |
| macOS | `~/Library/Application Support/remote-claude/` |
| Windows | `%APPDATA%\remote-claude\` |

Закрытый ключ создаётся на компьютере и не отправляется на сервер. В профиль сохраняются адрес, пользователь, fingerprint сервера и путь к ключу, но не bootstrap-ключ приглашения.

## 6. Файлы, команды и конфигурация проекта

В обычном режиме:

- исходники остаются на компьютере и монтируются на сервер через SSHFS;
- Read/Edit работают с этими же локальными файлами;
- Bash/PowerShell, Git, сборки, тесты, hooks и stdio MCP выполняются локально;
- HTTP hooks и HTTP/SSE MCP устанавливают соединения с компьютера, включая localhost и VPN;
- `CLAUDE.md`, вложенные инструкции, `.claude/rules`, skills, commands, agents и проектные настройки доступны Claude;
- личный `~/.claude` компьютера не импортируется.

Команды получают обычные права вашего пользователя и **не ограничены каталогом проекта**. Ограничен файловый SFTP-интерфейс и пути локального поиска, а не произвольная команда. Постоянный `cd` за пределы проекта адаптером отклоняется; при необходимости используйте абсолютный путь в самой команде с учётом риска.

Для ускорения применяются короткие кеши метаданных и конфигурации, пакетное чтение небольших файлов и локальный ripgrep. Содержимое обычного файла не кешируется между открытиями. После локального редактирования изменения обычно видны через 1–3 секунды плюс сетевая задержка.

Если конфигурация сложная или кеш мешает диагностике:

```sh
remote-claude --fresh-metadata .
```

Этот режим отключает короткие кеши и использует более медленное штатное обнаружение конфигурации. `--server-search` принудительно возвращает поиск через серверный ripgrep.

При чтении executable-настроек Claude может показывать транспортный адаптер вместо исходной команды. Локальный редактор продолжает показывать оригинал; при записи адаптер преобразуется обратно.

## 7. Обрывы связи

Интерактивный клиент автоматически переподключается с нарастающей паузой от 1 до 16 секунд:

- обычный режим продолжает выбранный разговор;
- серверный режим подключается к прежнему tmux-сеансу без новой ветки и пересборки;
- `Ctrl+C` прекращает попытки.

Незавершённая команда могла успеть выполниться до обрыва. Мост не повторяет её автоматически: сначала проверьте состояние проекта и результат. Запросы `--print` также не повторяются автоматически.

В обычном режиме компьютер должен оставаться включённым. Для автономной задачи используйте `--server`.

## 8. Задача целиком на сервере

### Подготовка

Администратор должен включить для аккаунта серверный режим. На сервере нужны Docker, tmux, sudo и, для pull request, `gh`.

Один раз настройте доступ к Git-хостингу:

```sh
remote-claude ssh
gh auth login
exit
```

Если `origin` использует SSH, добавьте на сервере SSH-ключ с доступом к репозиторию. Не передавайте ключи через публичные каналы.

### Запуск

Сервер получает только сведения о репозитории и коммите, а не копию вашего рабочего дерева:

```sh
git push
remote-claude --server .
```

Текущий коммит должен существовать в `origin`. Незакоммиченные и неотправленные изменения не попадут в задачу. Сервер создаёт ветку `claude/<исходная-ветка>-<дата>-<время>`.

Отсоединение от tmux: `Ctrl+B`, затем `D`. После этого компьютер можно выключить. Повторная команда подключается к запущенной задаче:

```sh
remote-claude --server .
```

После завершения tmux/Claude продолжите тот же checkout:

```sh
remote-claude --server --resume .
```

Сохраняются серверная ветка и незакоммиченные серверные изменения. Если задачи для проекта ещё не было, команда сообщит об ошибке и не создаст новую ветку.

### Образ проекта

По умолчанию используется Ubuntu 24.04 с Git, Go, Node.js, Python и build-essential. Собственный образ задаётся файлом `.remote-claude/Dockerfile`:

```dockerfile
FROM remote-claude-job-base:latest
RUN apt-get update && apt-get install -y --no-install-recommends postgresql-client
```

В build context попадает только `.remote-claude`. Образ должен использовать glibc и содержать Git. Docker socket внутри задачи недоступен.

### Git и параллельные задачи

- На аккаунт допускается до двух tmux-задач.
- Клиент пытается обнаружить уже запущенный контейнер того же репозитория под другим аккаунтом. Проверка не атомарна, видит только запущенные контейнеры и обходится осознанным `--server --force-new`.
- Разрешения Claude заранее разрешают ограниченный набор Git/PR-команд и запрещают распространённые варианты force-push и `gh pr merge`.
- Это не гарантия безопасности Git. Настройте branch protection и используйте токен без права слияния.
- Checkout находится в `~/server-jobs/`. Новая задача не перезапишет незакоммиченные остатки прежней.

Для уже существующего Git-checkout на сервере:

```sh
remote-claude night /абсолютный/путь/к/репозиторию
```

`night` не готовит новую ветку и не принимает смонтированный локальный проект.

## 9. Обновления

При подключении клиент читает манифест на закреплённом сервере. Если версия новее, клиент получает файлы по тому же SSH-соединению, проверяет SHA-256 и перезапускается. Исполняемый файл заменяется последним; ошибка обновления оставляет прежний клиент рабочим.

Манифест и файлы доверены тому же серверу — независимой цифровой подписи обновления нет. Development-сборки клиентом не устанавливаются.

Ручная установка архива без приглашения сохраняет профиль и ключ:

```sh
sh ./install.sh
```

Проверка версии и исходного коммита:

```sh
remote-claude version
```

## 10. Диагностика и ограничения

При проблемах сохраните ОС, архитектуру, вывод `remote-claude version`, результат `remote-claude --check .` и текст ошибки. Не прикладывайте приглашения, закрытые ключи, `.credentials.json` или содержимое приватного проекта.

Полезные команды:

```sh
remote-claude ssh
remote-claude --check .
remote-claude --fresh-metadata --check .
```

Учитывайте границы совместимости:

- адаптер закреплён на Claude Code 2.1.292;
- высокий RTT всё равно влияет на ввод и файловые операции;
- события inotify с компьютера не передаются;
- Windows сохраняет свои правила регистра, блокировок, ACL и symlink;
- PowerShell `-File` в закреплённой версии не адаптирован;
- LSP/собственные бинарники/JavaScript-моды плагинов, OAuth сторонних MCP, нативная OS-sandbox и worktrees вне экспортированного дерева не адаптированы;
- Windows и macOS кросс-компилируются, но требуют проверки на реальных системах;
- серверные контейнеры предназначены для изоляции инструментов и ресурсов, а не недоверенных пользователей.

Архитектура и модель безопасности подробно описаны в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) и [SECURITY.md](SECURITY.md). Настройка собственного сервера — в [ADMIN.ru.md](ADMIN.ru.md).
